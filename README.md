# Measuring cultural polarization across social groups

Replication code for the Master's thesis

> **Measuring cultural polarization across social groups: a machine learning classification approach**
> Egle Caudullo, ENSAI, academic year 2025-2026.
> Internship at CREST (ENSAI) and CREM. Supervisors: François Portier (CREST, ENSAI) and Emeline Bezin (CNRS, CREM).

The thesis is in [`thesis/Master_thesis_2026.pdf`](thesis/Master_thesis_2026.pdf).

## What the thesis does

Using the World Values Survey Wave 7 U.S. sample (n = 2,579 after filtering and
imputation), the analysis runs in two stages.

1. **Do value answers divide Americans into groups?** The 198 value items are
   clustered in three representations: z-score PCA (KM-PC2, KM-PC5), a 2D UMAP
   embedding (KM-UMAP) and the Gower dissimilarity (PAM). HDBSCAN serves as a
   density-based check that imposes no k. Several kinds of evidence are
   compared across k = 2..6:
   - internal criteria;
   - distance distributions;
   - density surfaces;
   - a fractional hedonic game.
2. **How far can membership be recovered from observable characteristics?**
   The held-out political (60 items) and sociodemographic (27 items) blocks
   predict membership in the k = 3 partition. The predictors are multinomial
   logit, LASSO and random forests, with 5-fold cross-validation.

Main findings:
- No criterion identifies a number of groups: value orientations form a
  continuum.
- Three groups are retained on interpretive grounds.
- Politics recovers membership better than social condition, and neither comes
  close to what discrete groups would allow.

## Data

The WVS data **cannot be redistributed** and are not included. To replicate:

1. Register at the World Values Survey website
   (<https://www.worldvaluessurvey.org>, WVS Wave 7, 2017-2022).
2. Download the United States file in CSV format,
   `WVS_Wave_7_United_States_Csv_v5.1.csv` (archive USA_2017_WVS-W7_v01_M).
3. Save it as `data/raw/WVS_Wave_7_United_States_Csv_v5.1.csv`.

Everything under `data/` and `results/objects/` is generated by the scripts
and is not tracked by git, because it is respondent-level.

## How to run

Run the scripts in numerical order, folder by folder. Each script starts with
`source(here::here("R", "00_setup.R"))` and can also be run piece by piece in
RStudio. Each one reads only what earlier scripts have saved.

| Order | Script | Output |
|---|---|---|
| 1 | `01_data/01_import_data.R` … `08_descriptive_stats.R` | analysis sample, codebook, descriptives |
| 2 | `02_clustering/01_pca_kmeans.R`, `02_umap_kmeans.R`, `03_gower_pam.R` | the partitions |
| 3 | `02_clustering/04_concordance.R` | `all_clusters.rds` |
| 4 | `02_clustering/05_hdbscan.R`, `06_hdbscan_vs_kmeans.R` | HDBSCAN partitions |
| 5 | `02_clustering/07_align_clusters.R` | **canonical** `results/objects/clusters/all_clusters_aligned.rds` |
| 6 | `03_structure/*`, `04_profiles/*` | structure evidence and cluster profiles |
| 7 | `05_recovery/01_recovery_k3.R` → `02_recall_k3.R` | k = 3 recovery |
| 8 | `05_recovery/03_geography.R` → `05_run_all_blocks.R` | all-k recovery |
| 9 | `05_recovery/06_composition_by_cluster.R` | Figure 4.9 |
| 10 | `06_robustness/*`, `07_figures/*` | any order after the steps above |

### Heavy steps

The computationally heavy steps are:
- the random-forest imputation (`01_data/04_preprocess_impute.R`);
- the 2579 x 2579 Gower matrix and PAM (`02_clustering/03_gower_pam.R`);
- UMAP at 20 and 50 dimensions (`02_clustering/05_hdbscan.R`);
- the all-k benchmark (`05_recovery/05_run_all_blocks.R`). The script notes
  about 80 minutes per block with permutation importance, and 6 blocks are run.

Two scripts run in parallel with `future`: `05_recovery/01_recovery_k3.R` and
`04_recovery_all_k.R`. They use `future.seed = TRUE`, so results are
reproducible. All other scripts are sequential.

## Known limitations

The cleanup was behaviour-preserving: seeds, parameters and models are those
used for the thesis. The following points are documented but not changed.

**Possible issues in the analysis**
- **Figure 4.1:** the panel titled "Euclidean distance on 2 PCs" is computed
  on all 198 principal components (`dist(pca_scores)`).
- **Gower dissimilarity:** all 198 items enter `cluster::daisy()` as unordered
  factors, so Gower treats them as nominal. Section 3.2.3 describes an ordinal
  treatment.
- **Two UMAP layouts:** the KM-UMAP labels come from the embedding of
  `02_clustering/02_umap_kmeans.R`. HDBSCAN and Figures 4.4-4.5 use the
  embedding of `02_clustering/05_hdbscan.R`. The two 2D layouts are very close
  but not identical: re-running k-means (k = 3) on the second gives ARI = 0.945
  with the stored KM-UMAP labels.

**Thesis items with no script in this repository**
- the simulated ceiling of Section 4.3;
- Table 4.6;
- the three-panel PDF of Figure 4.2 (each panel is produced separately);
- LaTeX writers for Tables 4.4, 4.7, 4.8 and A.11-A.14 (they are printed to
  the console and saved as `.rds`);
- the no-information rate in the k = 3 script.

**Incomplete or non-reproducible inputs**
- In the archived run of `05_recovery/05_run_all_blocks.R`, the
  `pol_dem_geo` block never finished, and `cross_block_metrics.rds` predates
  the final blocks.
- `06_robustness/11_gower_pam_with_politics.R` reads
  `data_imputed_selected_pol.rds`. That file comes from a separate run of the
  imputation restricted to the value and political items, and is not rebuilt
  by `04_preprocess_impute.R`.

**Robustness scripts**
- They are kept as they were used. Some need packages that are not loaded by
  the setup (for example `vegan` in `13_pca_minmax_desmet.R`).
